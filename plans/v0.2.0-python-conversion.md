# pdf-edit-mcp v0.2.0 — TypeScript → Python (FastMCP) conversion

Status tracker. Authoritative plan for converting the MCP wrapper from a
TypeScript MCP server (`src/index.ts` + Zod) that spawns a Python `bridge.py`
into a single in-process Python FastMCP server at engine-0.2.0 parity.

## Why
- The wrapper already requires Python (`bridge.py` imports `pdf_edit_engine`); the
  TS layer (~2363 LOC) exists only to spawn-and-proxy `bridge.py` (1658 LOC).
- Converting drops the second runtime (Node), deletes the subprocess/IPC failure
  class, and gives a single language/release cadence with the engine.
- The premise of the original TS decision ("MCP SDK is TS-native") is obsolete:
  the official `mcp` Python SDK (FastMCP) is first-class.

## Target
- Package `pdf-edit-mcp` on PyPI; import package `pdf_edit_mcp`.
- Engine imported in-process; no subprocess, no Node.
- 38 tools + 3 prompts, byte-identical tool names + descriptions where possible.
- `mcp>=1.27.2,<2`, `pdf-edit-engine>=0.2.0,<0.3`, Python >=3.10.
- Distribution: `uvx pdf-edit-mcp`; `server.json` → registryType pypi.

## Architecture / layout
```
src/pdf_edit_mcp/
  __init__.py        __version__
  server.py          FastMCP instance, instructions, engine_lock, version gate, main()
  constants.py       all caps (single source of truth, ported from constants.ts)
  validation.py      8-check path safety + Pydantic path types + shared models (BBox/EditItem/BlockReplacement)
  serialize.py       _serialize_edit_result + aggregate-fidelity helpers (exact wire shapes)
  tools_read.py      9 read/analysis tools
  tools_edit.py      7 text/block edit tools (+ password on 7, + fit on 2)
  tools_sections.py  detect/swap/replace_section + helpers (verbatim port of the bridge algorithms)
  tools_document.py  15 wrapper tools
  tools_annotations.py 4 annotation tools
  prompts.py         3 MCP prompts (verbatim text)
tests/                pytest port of validation/security/bridge suites + v0.2.0 tests
```

## Key decisions (incl. re-audit corrections)
1. Reuse bridge.py logic verbatim where possible; keep `_serialize_edit_result`'s exact
   emitted shape (tests pin it) — do NOT swap to `EditResult.to_dict()` yet.
2. `extra="forbid"` on NESTED Pydantic models only (BBox/EditItem/BlockReplacement); accept
   FastMCP's native top-level param behavior (don't contort to reject extra top-level keys).
3. Error model: catch engine `PDFEditError` subclasses → raise `ToolError` with the classified
   message + hint preserved. Numeric JSON-RPC codes (-32001..-32004) retire (transport artifact);
   ported tests assert message/hint content, not codes.
4. Engine-version gate in `main()` before `mcp.run()` (stderr + `sys.exit(2)`), mirroring bridge.
5. Engine is NOT thread-safe → module-level `engine_lock` serialises all engine calls.
6. `password` ONLY on the 12 direct-verb tools (5 locator reads + replace_text/replace_single/
   batch_replace + replace_block/batch_replace_block/delete_block/insert_text_block). EXCLUDE
   composite tools (inspect, detect/swap/replace_section) + password-less verbs
   (detect_paragraphs, analyze_subset, get_annotations) — honest scoping.
7. `fit="none"|"shrink"` on pdf_replace_block + pdf_batch_replace_block.
8. Overwrite-warning (output_path==pdf_path): APPEND to engine warnings (root-fix the TS bug
   that overwrote them), don't replicate the overwrite.
9. Tool function names = exact `pdf_*` MCP names (incl. `pdf_delete_annotation_v2`).
10. In-place conversion on branch `feat/v0.2.0-python`; TS stays in git history.
11. npm `@aryanbv/pdf-edit-mcp` → `npm deprecate` with a pointer to PyPI/uvx (publish by user).

- `.strict()` parity: confirm/accept FastMCP schema behavior; enforce on nested models.
- Wire-shape regressions: ported bridge.test.ts assertions are the guardrail.
